## Two files that carry no estimates

`nb8_r1a_placebo_precommit.csv` and `nb8_r1b_placebo_nongating.csv` are
included because they are what those two runs produced, and a replicator who
reran them should get the same thing rather than wonder why they are absent.
Both are all-empty: every row reports `n_cells = 0`.

The pre-commit arm found 27 placebo-treated repositories against 13,508
controls and no usable cell at `MIN_CELL = 10`. The arm is simply too small in
this panel; `results_main.csv` carries the same conclusion for `T7_precommit`,
where the group-time columns are also empty.

The non-gating arm found 8,790 placebo-treated repositories and **zero**
controls, which is a configuration failure rather than a sample limitation:
with no control group there is nothing to difference against. The two
successor runs fixed it by changing the comparison group, and they are the
ones the paper reports: `nb8_r1b_placebo_nyt.csv` against not-yet-treated
repositories, and `nb8_marginal_placebo.csv` against matched marginal
adopters. Section VI-C rests on the second.

Regenerating any of these needs the derived panel; see `../data/README.md`.

## The per-stage summaries

Nine JSON files, one per pipeline stage, each written at the end of its
notebook. They hold the reported counts in machine-readable form, so a
reviewer can check a number in Section III or IV without rebuilding the panel.

| File | Carries |
|---|---|
| `gateC.json` | the bundling pilot: 56 of 80 multi-safeguard repositories bundled |
| `nb1_summary.json` | 3,734,686 file versions, 20,155 eligible, 4,903 Treatment B events, `bundling_3mo` = 0.717043 |
| `nb2_summary.json` | the 3,000-repository config sample, 5 scan failures, per-arm adopter and control counts |
| `nb3_summary.json` | outcome totals over 1,390,874 repository-months |
| `nb3b_summary.json` | bot shares per outcome and the human-only totals |
| `nb4_summary.json` | panel size, `filled_zero_share` = 0.17136, the MDE |
| `nb5_summary.json` | Treatment A estimates, the pre-trend test, `naive_sum_z2` |
| `nb6_summary.json` | bot contrast per outcome, 2 sign flips, 16 fits |
| `nb8_summary.json` | the reconciliation gate, all five runs, the estimator used |

Two things recorded in `nb8_summary.json` are worth reading directly:
`estimator` names the estimator the reported run used, and `r5_removal`
records that run's status rather than a result.
